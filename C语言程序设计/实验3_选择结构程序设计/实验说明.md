## 任务 1：充值积分

### 问题分析

1. 只有“金额是否达到 1000 元”两种情况，用 `if…else` 双分支实现。
2. `float` 型变量 `amount` 存放金额，`int` 型变量 `point` 存放积分。
3. `amount >= 1000` 时按 `point = (int)(amount / 100.0f)` 计算，`(int)` 完成取整；否则不奖励。

| 输入 | 输出 |
| --- | --- |
| 1200 | 本次充值可奖励 12 积分 |
| 800 | 充值金额不足 1000 元，本次充值不奖励积分 |

## 任务 2：余额与消费

### 问题分析

1. 结果只有“刷卡成功”和“余额不足”两种，用 `if…else` 实现。
2. 条件写作 `cost <= balance`，保证消费金额等于余额时也能刷卡成功。
3. 刷卡成功时执行 `balance = balance - cost` 并输出新余额；否则余额不变。

| 余额 | 消费 | 输出 |
| --- | --- | --- |
| 1000 | 300 | 刷卡成功，消费 300.00 元，当前余额 700.00 元 |
| 500 | 800 | 余额不足，请充值 |

## 任务 3：三个数的最大值

### 问题分析

1. 三个数需两两比较，采用 `if` 语句嵌套。
2. 先比较 `a` 与 `b`，取两者中较大的一个，再与 `c` 比较，两次比较后即为最大值。
3. 比较使用 `>=`，两数相等时结果同样正确。

| 输入 | 输出 |
| --- | --- |
| 3.5 7.2 4.8 | 最大值是 7.20 |

## 任务 4：水果计价

### 问题分析

1. 按重量分三段计价，用 `if…else if…else` 多分支实现。
2. `weight < 2` 时不打折；`weight < 5`（即 2≤重量<5）时九折；否则八折。
3. `else if` 只在前一条件不成立时判断，故第二段只需写 `weight < 5`。

| 重量（kg） | 单价（元/kg） | 输出 |
| --- | --- | --- |
| 3 | 6 | 应付 16.20 元（九折） |
| 6 | 5 | 应付 24.00 元（八折） |

## 任务 5：菜单欢迎提示

### 问题分析

1. 菜单取值为 1、2、3 三个等值分支，用 `switch…case` 比多分支 `if` 更清晰。
2. 输出菜单说明后用 `scanf` 读入 `menu`。
3. 每个 `case` 末尾用 `break` 跳出；其他取值由 `default` 提示输入有误。

| 输入 | 输出 |
| --- | --- |
| 1 | 欢迎进入一卡通查询余额功能 |
| 2 | 欢迎进入一卡通消费功能 |
| 3 | 欢迎进入一卡通充值功能 |
| 其他 | 输入的菜单选项有误，请输入1、2或3！ |

## 任务 6：一卡通充值管理

### 问题分析

程序初始化 `balance = 1000.0`，再按 `menu` 分支：

- **菜单 1（查询余额）**：直接输出当前 `balance`。
- **菜单 2（消费）**：读入 `cost`，`cost <= balance` 时扣款并输出余额，否则提示余额不足。
- **菜单 3（充值）**：读入 `amount`，先执行 `balance += amount`，再按“充值到账后的累计余额”判断积分。
- **其他菜单**：`default` 提示输入有误。

### 积分判断说明

按“充值到账后的累计余额”判断，条件顺序如下：

1. `amount >= 1000 && balance >= 2000`：奖励 100 积分；
2. `(amount >= 500 && balance >= 1000) || amount >= 800`：奖励 50 积分；
3. `amount >= 200`：奖励 20 积分；
4. 其他情况：不奖励积分。

条件 2 中同时使用了逻辑与、逻辑或，代码中用括号明确运算顺序，避免歧义。
